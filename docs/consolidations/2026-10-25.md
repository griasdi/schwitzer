## Target picture

- **App core.** `app/mod.rs` is the Elm hub: `Message`, `App`, `update` with one-line arms, `view`, `subscription`. Every lifecycle lives in its own `impl App` file (`plugins.rs`, `updates.rs`, `debug_session.rs`, `tasks.rs`, `projects.rs`, `resume.rs`), and the iced-free decisions, including every status lamp line, sit in `logic.rs`. Room-derived facts have one owner: `Rooms` for room state, the client for the debug inbox.
- **App views and look.** Views compose shared widgets (`widgets.rs`: bar, segment, group head, member tag, fold button, picker, input), and pages and empty states live in view files, not in the hub. Tokens are read only by `theme.rs`; new surfaces use the spacing scale.
- **App logic and local services.** `debug.rs` owns the debug folder layout and the stream listing that both the worker and the MCP tool read. `settings.rs` keys projects by typed `(RoomId, project id)` everywhere. `update.rs` keeps only what is the app's: the AppImage, the restart and the update state.
- **Agent integration.** `mcp/tools.rs` resolves a room once, moves it out of the joined list and reads its debug session through `RoomRef::debug`. The plugin has one select helper and one poll loop; its notices are constants.
- **Client.** `schwitzer-client` keeps the debug inbox and rejoin wish beside the room state and drops them on every path that drops a room; `ClientEvent::DebugInbox` says what is new.
- **Server.** `rpc.rs` validates request shape (every text through `text()`), `store.rs` holds the stored rules, `hub.rs` only delivery and sessions, `debug.rs` the debug session rules. One GCRA serves both budgets. `Options` cannot hold an updater without a release check.
- **Proto.** Wire types and the rules both sides share; `ServerAddr::authority` is the one `host:port` form.
- **Release and update.** `schwitzer-release` owns everything about a GitHub release: its JSON shape, the dev release fetch, the timeouts, the user agent, download plus check, and the program-file swap and archive extraction on every OS.
- **Tooling and docs.** ARCHITECTURE.md is the reference and the other documents and diagrams agree with it and the code; CI keeps the two licence lists equal.
